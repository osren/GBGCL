## 架构问题分析

### 问题 1: 粒球只在特定 epoch 触发
```
if args.use_gb and (epoch % args.gb_rebuild_every == 0):
    z_new = granule_diffuse_and_write(...)
```
- `gb_rebuild_every=50`：只有在 epoch 0 构建一次
- 后续 49 个 epoch 使用**相同的粒球结构**
-  embeddings 更新后粒球没有同步更新

### 问题 2: 粒球回写后不再参与后续计算
```python
# h 是原始 GCN 输出
z_new, gb_sizes, H_ball = granule_diffuse_and_write(h, ...)
h_pred = online.predictor(z_new)  # z_new 只用了这一次
```
- `z_new` 只在当下这个 epoch 的 predictor 中使用
- 下一个 epoch 的 `h` 仍然是原始 GCN 输出，**没有继承扩散后的信息**
- 粒球信息**没有累积效应**

### 问题 3: 球级损失权重太小
```python
loss = loss_node + 0.05 * loss_ball_scatter + 0.02 * loss_ball_infonce
# 主要由 BYOL (Node Level) 主导
```

### 问题 4: Target Encoder 没有使用粒球信息
```python
# online 使用 h
h, h_pred, h_target = online(data.x, data.edge_index)

# target 也用原始输入，没有粒球增强
with torch.no_grad():
    h_target,_, = self.target_encoder(x, edge_index)
```
- online 和 target 两个分支都没有使用粒球增强

## 可能的改进方向

| 改进点 | 当前问题 | 建议 |
|--------|--------|------|
| 粒球更新频率 | 只在 epoch 0 构建 | 每 5-10 个 epoch 重建，或每 epoch 重建 |
| 信息传递 | 下一个 epoch 不继承扩散结果 | 将扩散结果写入节点特征，参与下一轮 GCN |
| Target 分支 | 无粒球增强 | 对 target 也做粒球扩散 |
| 损失权重 | 球级 loss 太弱 | 增大 ball_loss_weight (0.1-0.3) |
| 架构设计 | 单次扩散，无累积 | 设计迭代式粒球传播 |
