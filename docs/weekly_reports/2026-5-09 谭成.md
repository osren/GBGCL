## 二、Option A2：多 quity 集成投票方案

### 2.1 设计思路

为了解决粒球质量函数（quity）需要手动选择的问题，提出了一种自适应的多 quity 集成投票方案。该方案的核心思想是在每次粒球重建时，并行用 homo、detach、edges 三种质量函数分别构建粒球，然后通过质量评估函数计算每种粒球结构的得分，最后基于 softmax 权重选择最优结果。

在具体实现上，质量评估函数综合考虑了两个维度：球间分离度（不同球心之间的相似度，越低越好）和球内紧凑度（球内节点到球心的距离，越低越好）。通过这两个指标的加权组合，可以量化评估不同 quity 构建的粒球质量。权重计算采用 softmax 归一化，温度系数可以控制投票的激进程度。

### 2.2 新增参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--gb_ensemble` | 启用 ensemble 投票模式 | false |
| `--gb_ensemble_quities` | 投票的 quity 列表 | homo,detach,edges |
| `--gb_ensemble_temp` | softmax 温度系数 | 1.0 |
| `--gb_ensemble_select` | 选择策略，可选 hard 或 soft | hard |

### 2.3 实验结果

在 Photo 数据集上进行了 50 个 epoch、3 次 trial 的测试，结果显示 Ensemble 模式能够正常工作并自动选择 quity。测试日志示例如下：

```
[Ensemble] quity=homo, weight=0.3344
[Ensemble] quity=detach, weight=0.3296
[Ensemble] quity=edges, weight=0.3360
[Ensemble] Selected: edges
```

三种 quity 的权重非常接近（均在 0.33 左右），说明在 Photo 数据集上三种质量函数产生的粒球结构相似度较高。该结果也表明 Photo 数据集的结构特性使得不同 quity 之间的差异不明显，这是后续需要关注的问题。

## 三、Option B：架构优化分析

### 3.1 架构梳理

对当前粒球模块的训练流程进行了系统梳理，明确了各个模块的作用和相互关系。当前架构包含以下主要组件：GCN Encoder（Online 和 Target 双分支）、BYOL 对比损失、粒球构建模块（Granular）、球图扩散模块（K-step diffusion）、回写机制（残差式融合）以及球级损失（Ball Scatter 和 Ball InfoNCE）。

### 3.2 架构改进方向

通过分析，提出了后续优化的几个具体方向。方向一是增加粒球更新频率，当前只在 epoch 0 构建一次，建议每 5-10 个 epoch 重建以保持粒球与当前嵌入的同步。方向二是增强信息传递，将粒球扩散结果写入节点特征，使下一轮训练能够继承扩散信息。方向三是 Target 分支增强，对 Target Encoder 的输出也进行粒球扩散，提升双分支的粒球增强效果。方向四是调整损失权重，适当增大球级损失权重（如从 0.05 提升至 0.2-0.3），使粒球模块在训练中发挥更重要的作用。

### 3.3 初步验证

针对方向四（增大球级损失权重），本周进行了初步验证测试。在保持其他参数不变的情况下，分别测试了不同的 ball_loss_weight 和 ball_infonce_weight 配置，验证了增大损失权重的可行性。
