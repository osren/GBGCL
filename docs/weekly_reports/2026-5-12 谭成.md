### 2.2 发现的问题

**问题1：时间维度不连续**
- 粒球只在 `gb_rebuild_every=10` 的 epoch 生效（如 epoch 0, 10, 20, 30, 40）
- 其他 epoch 粒球损失为 0，没有参与训练
- 90% 的训练时间粒球模块不工作

**问题2：信息维度高度相似**
- `cos_sim` 接近 1.0（0.9996），说明 h 和 z_new 几乎同方向
- 粒球扩散只是改变向量长度，没有改变方向
- 没有引入新的语义信息

**问题3：粒球纯度已很高**
- 粒球纯度 90.7%，说明划分算法已经很好
- 问题不在划分，而在扩散方式

---

## 三、问题根因分析

当前粒球模块的核心问题：**没有真正融入训练流程**。

1. **架构问题**：粒球只在特定 epoch 构建，不跟随嵌入动态更新
2. **信息问题**：扩散结果与原始嵌入高度相似（cos_sim > 0.99）
3. **损失问题**：BYOL 损失主导，粒球损失权重太小

---

## 四、改进方案

针对发现的问题，提出以下改进方向：

### 方案1：增大 beta 扩散系数

当前 beta=0.2，增大它会让更多跨球信息混合。

```bash
# 测试命令
python train.py --dataset_name Photo --use_gb --gb_beta 0.5 ...
python train.py --dataset_name Photo --use_gb --gb_beta 0.8 ...
```

### 方案2：降低 alpha 融合系数

当前 alpha=0.6，降低它会让更多粒球信息参与。

```bash
# 测试命令
python train.py --dataset_name Photo --use_gb --gb_alpha 0.3 ...
python train.py --dataset_name Photo --use_gb --gb_alpha 0.1 ...
```

### 方案3：改变 w_mode

切换权重模式，强制不同方向的信息传播。

```bash
# 测试命令
python train.py --dataset_name Photo --use_gb --gb_w_mode topo ...
python train.py --dataset_name Photo --use_gb --gb_w_mode center ...
```
