## 二、踩过的坑（避免重犯）

### 2.1 BTCM scaffold 三个连续 bug

1. **维度不匹配**：`granule_diffuse_and_write` 返回 `HK` 形状 `[B, hidden_dim=1024]`，而 `BallConv.ball_dim` 默认 64 → 拼接炸。**修法**：`--gb_ball_emb_dim` 默认改为 1024 匹配 hidden_dim。
2. **epoch 0 无 prev_H_ball**：原代码 `if prev_GB_node_list is not None and prev_H_ball is not None:` 在 epoch 0 走 else 分支不传 `gb_ball_feat`，BallConv assert 炸。**修法**：BTCM 通路在 epoch 0 用 `torch.zeros(N, ball_dim)` 占位。
3. **train_target 没传 ball_feat**：Target 编码器也用 BallConv，但 `train_target` 调用时没传。**修法**：在 `run()` 顶层统一构建 `gb_ball_tensor`，train_online 与 train_target 共享。

### 2.2 服务器命令被换行截断

用户的 SSH 终端宽度不足，命令被自动换行后 bash 把每行当独立命令解析，导致 `--num_epochs: command not found` 类错误。**修法**：长命令一律写到 `.sh` 脚本里再 `bash`，不要再直接敲长命令。

### 2.3 data.py 大小写 / 路径

PyG `Amazon.name.capitalize()` → `Photo`（匹配服务器大写目录），但 Photo 数据集必须用**绝对路径** `--data_dir`，否则 `read_npz` 找不到文件（默认 `../../datasets` 在 nohup 下 cwd 不可靠）。
